# Журнал проверки репликации

Репликация проверяется на стенде Docker (`replication/setup.sh`).
Таблица заполняется по мере фактического выполнения проверок на стенде.

| № | Что проверяется | Команда | Ожидаемый результат | Факт |
|---|---|---|---|---|
| 1 | Запуск узлов | `docker compose up -d` | 4 контейнера в состоянии Up | |
| 2 | РОК: НСИ ЦО → филиал | `UPDATE tariffs ...` на master | изменение появилось на slave | |
| 3 | РБОК: клиенты филиал → ЦО | `INSERT INTO universities ...` на slave | запись появилась на master | |
| 4 | РКД: данные филиала → консолидация | `INSERT INTO equipment_units ...` на slave | запись появилась на consol | |
| 5 | Состояние репликации | `SHOW SLAVE STATUS` | Slave_IO_Running=Yes, Slave_SQL_Running=Yes | |
| 6 | Распределённый запрос | поиск модели по узлам | собраны данные всех ответивших узлов | |
| 7 | Распределённая транзакция | бронирование в другом филиале | экземпляр забронирован атомарно | |

Заполняется бригадой после запуска Docker-стенда (требуется Docker Desktop или
Docker Engine). Локальная проверка SQL без репликации уже выполнена:
см. `query_results.txt` и `integrity_tests.txt`.
