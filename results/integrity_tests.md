# Протокол проверки ограничений целостности

Проверка выполнена командой
`mysql --force < tools/integrity_tests.sql` (полный вывод — в `integrity_tests.txt`).
Часть инструкций намеренно нарушает ограничения — для них ожидается ошибка.

| № | Проверяемое правило | Ожидание | Фактический результат |
|---|---|---|---|
| P1 | Корректная заявка | успех | заявка добавлена успешно |
| N1 | Филиал заявки не совпадает с обслуживающим филиалом вуза | ошибка | `Заявка: филиал не совпадает с обслуживающим филиалом вуза` |
| N2 | Тариф относится к другой модели | ошибка | `Позиция заявки: тариф относится к другой модели` |
| P2 | Корректная позиция; сумма заявки пересчитана триггером | успех | позиция добавлена, REQ_SUM обновлена |
| N3 | Период позиции выходит за период заявки | ошибка | `Позиция заявки: период выходит за период заявки` |
| N4 | Сумма заявки изменена вручную неверно | ошибка | `Заявка: сумма не равна сумме позиций` |
| N5 | Недопустимый статус экземпляра техники | ошибка CHECK | `Check constraint 'chk_eq_status' is violated` |
| N6 | Дублирование паспорта представителя | ошибка UNIQUE | `Duplicate entry ... for key 'uniq_rep_passport'` |
| N7 | Пересекающиеся периоды выдач одного экземпляра | ошибка | `Выдача: периоды выдач одного экземпляра пересекаются` |
| N8 | Выдача экземпляра, находящегося в аренде | ошибка | `Выдача: экземпляр не свободен` |
| P3 | Возврат техники | успех, статус меняется | статус экземпляра изменён на `свободна` |

**Итог:** все 11 проверок дали ожидаемый результат; работа триггеров,
CHECK- и UNIQUE-ограничений подтверждена.
