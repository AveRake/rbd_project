# Руководство по запуску проекта CampusRent

Проект распределённой базы данных «Сервис аренды техники для высших учебных
заведений». В руководстве — все команды, порядок действий, проверки и типичные
ошибки.

---

## 0. Коротко: что делать в первую очередь

| Что нужно | Как | Время |
|---|---|---|
| 1. Загрузить БД и увидеть результат | Вариант А (одиночный сервер MySQL) | 10 минут |
| 2. Проверить ограничения и отчёты | `tools/run_local_demo.sh` | 2 минуты |
| 3. Запустить стенд репликации | Вариант Б (Docker) | 20 минут |
| 4. Показать систему в браузере | Веб-приложение (раздел 5) | 5 минут |

**Главное:** пункты 1, 2 и 4 у меня уже проверены на реальном сервере MySQL.
Пункт 3 (Docker-стенд) нужно запустить и проверить вам — на машине, где я
работал, демон Docker недоступен.

---

## 1. Что понадобится

Обязательное:

- **MySQL 8.0** или новее (для локального запуска) — либо **Docker Desktop**
  (для стенда репликации);
- терминал (bash / zsh / PowerShell);
- `git` — если будете работать с репозиторием.

Дополнительное:

- **PHP 8** с расширением `pdo_mysql` — для веб-приложения;
- **Python 3.9+** — для перегенерации данных, схем и графиков;
- **rsvg-convert** (`brew install librsvg`) — только для пересборки SVG в PNG;
- `python-docx` — только если будете пересобирать отчёт.

Клиенты СУБД (по желанию): DBeaver, DataGrip, phpMyAdmin.

## 2. Вариант А. Быстрый запуск на одном сервере MySQL

### 2.1. Подготовка

Установите MySQL 8.0 и запустите сервер. Проверьте подключение:

```bash
mysql -uroot -p -e "SELECT VERSION();"
```

Перейдите в папку проекта:

```bash
cd Проект_Сервис_аренды_техники
```

### 2.2. Загрузка базы данных

Скрипты выполняются **строго по порядку**:

```bash
mysql -uroot -p --default-character-set=utf8mb4 < sql/01_schema.sql
mysql -uroot -p --default-character-set=utf8mb4 < sql/02_reference_data.sql
mysql -uroot -p --default-character-set=utf8mb4 < sql/03_test_data.sql
mysql -uroot -p --default-character-set=utf8mb4 < sql/04_views.sql
mysql -uroot -p --default-character-set=utf8mb4 < sql/05_triggers.sql
mysql -uroot -p --default-character-set=utf8mb4 < sql/06_indexes.sql
mysql -uroot -p --default-character-set=utf8mb4 < sql/07_users_grants.sql
```

Почему именно такой порядок: файл `03_test_data.sql` загружает данные **до**
создания триггеров (`05_triggers.sql`). Иначе триггеры проверяли бы каждую
строку при массовой загрузке.

Если прав на создание ролей и пользователей нет, шаг `07` можно пропустить —
таблицы, представления, триггеры и отчётные запросы продолжат работать.

### 2.3. Проверка результата

```bash
mysql -uroot -p campusrent -e "
SELECT COUNT(*) AS таблиц FROM information_schema.tables
 WHERE table_schema='campusrent' AND table_type='BASE TABLE';
SELECT COUNT(*) AS представлений FROM information_schema.views
 WHERE table_schema='campusrent';
SELECT (SELECT COUNT(*) FROM equipment_units) AS техника,
       (SELECT COUNT(*) FROM requests)        AS заявки,
       (SELECT COUNT(*) FROM contracts)       AS договоры,
       (SELECT COUNT(*) FROM rentals)         AS выдачи;"
```

Ожидаемый результат: **22 таблицы, 10 представлений**,
775 единиц техники, 263 заявки, 114 договоров, 471 выдача.

### 2.4. Отчётные запросы

```bash
mysql -uroot -p --table --default-character-set=utf8mb4 < sql/08_queries.sql
```

Это 18 запросов: загрузка парка, структура парка, топ моделей, поступления,
динамика по месяцам, статусы заявок, затраты на ремонт, сроки аренды,
распределённый поиск техники. Все они выполняются без ошибок.

## 3. Проверка ограничений целостности и полный прогон

Одной командой (загружает БД заново, выполняет запросы и тесты):

```bash
bash tools/run_local_demo.sh "-uroot -pВАШ_ПАРОЛЬ"
```

Результаты сохраняются в:

- `results/query_results.txt` — вывод всех 18 запросов;
- `results/integrity_tests.txt` — протокол проверки ограничений.

Только тесты ограничений:

```bash
mysql -uroot -p --table --force < tools/integrity_tests.sql
```

Важно: **ошибки в этом файле — это ожидаемый результат**. Ключ `--force`
нужен, чтобы клиент не останавливался на первой ошибке. Вы должны увидеть
10 проверок: часть завершается ошибкой (запрещённые операции), часть —
успешно.

Примеры ожидаемых сообщений:

| Сообщение | Что проверялось |
|---|---|
| `Заявка: филиал не совпадает с обслуживающим филиалом вуза` | корректность заявки |
| `Позиция заявки: тариф относится к другой модели` | согласованность позиции |
| `Выдача: экземпляр не свободен` | запрет выдачи занятой техники |
| `Выдача: периоды выдач одного экземпляра пересекаются` | запрет двойной выдачи |
| `Заявка: сумма не равна сумме позиций` | защита суммы заявки |
| `Check constraint 'chk_eq_status' is violated` | проверка статуса техники |
| `Duplicate entry ... for key 'uniq_rep_passport'` | уникальность паспорта |

Подробная расшифровка — в `results/integrity_tests.md`.

## 4. Вариант Б. Стенд репликации (Docker)

Это **обязательная часть** работы по методическим указаниям: нужно показать
репликацию, а не только схему БД.

### 4.1. Запуск

1. Запустите Docker Desktop и дождитесь, пока значок кита в строке меню
   перестанет анимироваться.
2. Проверьте, что демон доступен:

```bash
docker info --format '{{.ServerVersion}}'
```

Если команда вернула версию — можно продолжать. Если ошибку
`Cannot connect to the Docker daemon` — Docker ещё не запустился.

3. Запустите стенд (занимает 2–4 минуты):

```bash
cd replication
bash setup.sh
```

Скрипт делает всё сам: поднимает контейнеры, ждёт их готовности, загружает
одинаковый снимок схемы и данных во все четыре узла, фиксирует позиции
бинарных журналов и включает репликацию. В конце он печатает состояние
каналов — ожидается `Slave_IO_Running: Yes` и `Slave_SQL_Running: Yes`.

Важно: если запускаете стенд повторно на уже созданных контейнерах, сначала
очистите их:

```bash
docker compose down -v
bash setup.sh
```

Скрипт поднимает 4 контейнера и настраивает репликацию:

| Контейнер | Роль | Порт |
|---|---|---|
| `mysql-master` | центральный офис, источник НСИ | 3306 |
| `mysql-slave` | филиал Санкт-Петербург | 3307 |
| `mysql-slave2` | филиал Казань | 3309 |
| `mysql-consol` | узел консолидации | 3308 |

### 4.2. Проверка трёх видов репликации

**Репликация с основной копией (РОК): справочники из ЦО в филиалы.**

```bash
docker exec -it mysql-master mysql -uroot -ppassword campusrent -e \
  "UPDATE tariffs SET TAR_PRICE = TAR_PRICE + 100 WHERE TAR_ID = 2011;"

docker exec -it mysql-slave mysql -uroot -ppassword campusrent -e \
  "SELECT TAR_ID, TAR_PRICE FROM tariffs WHERE TAR_ID = 2011;"
```

Цена изменилась на мастере и появилась на слейве — РОК работает.

**Репликация без основной копии (РБОК): клиенты.**

```bash
docker exec -it mysql-slave mysql -uroot -ppassword campusrent -e \
  "INSERT INTO universities (UN_ID,UN_NAME,UN_SHORT,UN_INN,UN_ADDRESS,UN_CITY,UN_BR)
   VALUES (9099,'Тестовый университет','ТЕСТВУЗ','9900000099','ул. Тестовая, 1','Москва','HQ');"

docker exec -it mysql-master mysql -uroot -ppassword campusrent -e \
  "SELECT UN_ID, UN_SHORT FROM universities WHERE UN_ID = 9099;"
```

Запись, добавленная в филиале, появилась в центральном офисе.

**Репликация с консолидацией (РКД): данные филиала в ЦО.**

```bash
docker exec -it mysql-slave mysql -uroot -ppassword campusrent -e \
  "INSERT INTO equipment_units (EQ_ID,EQ_INV,EQ_MOD,EQ_BR,EQ_STATUS,EQ_COND,EQ_ACQUIRE)
   VALUES (909900,'SPB-909900',201,'SPB','свободна',2,'2026-09-01');"

docker exec -it mysql-consol mysql -uroot -ppassword campusrent -e \
  "SELECT EQ_ID, EQ_INV, EQ_BR FROM equipment_units WHERE EQ_ID = 909900;"
```

**Состояние каналов репликации:**

```bash
docker exec -it mysql-slave  mysql -uroot -ppassword -e "SHOW SLAVE STATUS\G" | grep -E "Running|Master_Host"
docker exec -it mysql-consol mysql -uroot -ppassword -e "SHOW SLAVE STATUS\G" | grep -E "Running|Channel_Name"
```

Должно быть `Slave_IO_Running: Yes` и `Slave_SQL_Running: Yes`.

### 4.3. Что заполнить в проекте

После проверки откройте `results/replication_log.md` и заполните колонку
«Факт» — это ваш протокол испытаний.

### 4.4. Остановка

```bash
cd replication
docker compose down -v
```

Флаг `-v` удаляет тома с данными стенда.

## 5. Веб-приложение

```bash
cd app
DB_HOST=127.0.0.1 DB_PORT=3306 DB_USER=root DB_PASS=ВАШ_ПАРОЛЬ \
  php -S 0.0.0.0:8080
```

Откройте <http://localhost:8080>. Доступно:

- главное меню со статистикой и переходами к таблицам;
- просмотр и редактирование любой таблицы (добавление и удаление записей);
- отчётные формы (`reports.php`);
- представления: свободная техника, текущие выдачи, просроченные возвраты.

Чтобы подключиться к другому узлу РБД, укажите его порт в `DB_PORT`:
3306 — ЦО, 3307 — Санкт-Петербург, 3309 — Казань, 3308 — консолидация.

Полезный сценарий для демонстрации: попробуйте добавить выдачу для экземпляра
со статусом «аренда» — приложение покажет ошибку триггера. Это наглядно
подтверждает работу ограничений целостности.

## 6. Перегенерация данных, схем и графиков

Все генераторы детерминированы (фиксированное зерно), результаты

cd diagrams

for f in chart_*.svg; do rsvg-convert -w 1600 "$f" -o "${f%.svg}.png"; done

`sql/01_schema.sql`, `docs/03_Логическое_проектирование.md`,
`tools/gen_diagrams.py` (описание отношений `ATTR`) и отчёт.

## 8. Типичные проблемы

| Проблема | Причина и решение |
|---|---|
| `ERROR 1064 ... near 'CHANGE MASTER TO'` | В MySQL 8.4 команда заменена на `CHANGE REPLICATION SOURCE TO`. Используйте образ `mysql:8.0` — он уже указан в `docker-compose.yml` |
| `Access denied for user 'root'` | Неверный пароль. Если пароля нет, запускайте `mysql -uroot` без `-p` |
| `Table 'campusrent...' doesn't exist` | Скрипты загружены не по порядку. Начните с `01_schema.sql` |
| `ERROR 1644` в `integrity_tests.sql` | Так и должно быть: тесты намеренно нарушают ограничения |
| `docker compose: command not found` | Установите Docker Desktop; в старых версиях команда называется `docker-compose` |
| Роли не создаются в `07_users_grants.sql` | Нужны права на `CREATE ROLE`. Шаг можно пропустить: остальные объекты уже созданы |
| Приложение не подключается к БД | Задан пустой пароль. В `app/config.php` пустое значение переменной заменяется на `password` — укажите непустой пароль или поправьте файл |
| Кириллица превратилась в «кракозябры» | Добавьте `--default-character-set=utf8mb4` в команду `mysql` |
