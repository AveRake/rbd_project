# Запуск стенда CampusRent

Стенд разворачивается в Docker: четыре узла MySQL 8.0, между которыми настроены
репликация с основной копией, репликация без основной копии и консолидация
данных.

## 1. Требования

- Docker Desktop (или Docker Engine с плагином Compose);
- не менее 4 ГБ свободной оперативной памяти;
- свободные порты 3306, 3307, 3308, 3309.

Проверка, что демон Docker запущен:

```bash
docker info --format '{{.ServerVersion}}'
```

Команда выводит версию сервера. Сообщение
`Cannot connect to the Docker daemon` означает, что Docker Desktop ещё
не запустился.

## 2. Состав стенда

| Контейнер | Роль | Порт | server-id |
|---|---|---|---|
| `mysql-master` | центральный офис, источник справочников | 3306 | 1 |
| `mysql-slave` | филиал Санкт-Петербург | 3307 | 2 |
| `mysql-slave2` | филиал Казань | 3309 | 4 |
| `mysql-consol` | узел консолидации | 3308 | 3 |

Пароль пользователя `root` на всех узлах — `password`.

## 3. Запуск стенда

```bash
cd replication
bash setup.sh
```

Скрипт `setup.sh` поднимает контейнеры, дожидается их готовности, загружает
одинаковый снимок схемы и данных во все узлы, фиксирует текущие позиции
бинарных журналов и включает репликацию. Занятость — 2–4 минуты.

В конце печатается состояние каналов:

```
Slave_IO_Running: Yes
Slave_SQL_Running: Yes
```

Повторный запуск выполняется после очистки томов:

```bash
docker compose down -v
bash setup.sh
```

## 4. Проверка репликации

Команды выполняются из каталога `replication`.

Параметр `--default-character-set=utf8mb4` обязателен. Локаль внутри
контейнера — `C`, поэтому без этого параметра клиент `mysql` переключается
на `latin1`: русский текст искажается, а вставка в поле `VARCHAR(12)`
завершается ошибкой `ERROR 1406: Data too long for column 'EQ_STATUS'`.

### 4.1. Репликация с основной копией (РОК)

Справочники распространяются из центрального офиса в филиалы. Изменение
тарифа на узле ЦО должно появиться на филиале.

```bash
docker exec -it mysql-master mysql -uroot -ppassword --default-character-set=utf8mb4 campusrent -e \
  "UPDATE tariffs SET TAR_PRICE = TAR_PRICE + 100 WHERE TAR_ID = 2011;"

docker exec -it mysql-slave mysql -uroot -ppassword --default-character-set=utf8mb4 campusrent -e \
  "SELECT TAR_ID, TAR_PRICE FROM tariffs WHERE TAR_ID = 2011;"
```

### 4.2. Репликация без основной копии (РБОК)

Данные клиентов вводятся в любом узле и распространяются на остальные. Вуз,
добавленный на филиале, должен появиться и в центральном офисе, **и в другом
филиале**: параметр `log_replica_updates` в MySQL 8.0 включён по умолчанию,
поэтому узел-приёмник передаёт применённое событие дальше по цепочке.

```bash
docker exec -it mysql-slave mysql -uroot -ppassword --default-character-set=utf8mb4 campusrent -e \
  "INSERT INTO universities (UN_ID,UN_NAME,UN_SHORT,UN_INN,UN_ADDRESS,UN_CITY,UN_BR)
   VALUES (9099,'Тестовый университет','ТЕСТВУЗ','9900000099','ул. Тестовая, 1','Санкт-Петербург','SPB');"

docker exec -it mysql-master mysql -uroot -ppassword --default-character-set=utf8mb4 campusrent -e \
  "SELECT UN_ID, UN_SHORT FROM universities WHERE UN_ID = 9099;"

docker exec -it mysql-slave2 mysql -uroot -ppassword --default-character-set=utf8mb4 campusrent -e \
  "SELECT UN_ID, UN_SHORT FROM universities WHERE UN_ID = 9099;"
```

### 4.3. Репликация с консолидацией (РКД)

Данные филиала попадают в консолидированную копию. Экземпляр техники,
добавленный на филиале, должен появиться на узле консолидации.

```bash
docker exec -it mysql-slave mysql -uroot -ppassword --default-character-set=utf8mb4 campusrent -e \
  "INSERT INTO equipment_units (EQ_ID,EQ_INV,EQ_MOD,EQ_BR,EQ_STATUS,EQ_COND,EQ_ACQUIRE)
   VALUES (909900,'SPB-909900',201,'SPB','свободна',2,'2026-09-01');"

docker exec -it mysql-consol mysql -uroot -ppassword --default-character-set=utf8mb4 campusrent -e \
  "SELECT EQ_ID, EQ_INV, EQ_BR FROM equipment_units WHERE EQ_ID = 909900;"
```

### 4.4. Состояние каналов

В стенде работают шесть каналов: РОК (`mysql-master` → оба филиала), РБОК
(`mysql-slave` → `mysql-master`) и три канала консолидации на `mysql-consol`
(`hq`, `spb`, `kzn`).

```bash
docker exec -it mysql-slave  mysql -uroot -ppassword --default-character-set=utf8mb4 -e "SHOW SLAVE STATUS\G" | grep -E "Running|Master_Host|Last_Error"
docker exec -it mysql-slave2 mysql -uroot -ppassword --default-character-set=utf8mb4 -e "SHOW SLAVE STATUS\G" | grep -E "Running|Master_Host|Last_Error"
docker exec -it mysql-consol mysql -uroot -ppassword --default-character-set=utf8mb4 -e "SHOW SLAVE STATUS\G" | grep -E "Running|Channel_Name|Last_Error"
```

### 4.5. Распределённая транзакция (РТ-1, межфилиальное бронирование)

Скрипт реализует межфилиальное бронирование по протоколу двухфазной фиксации
на XA-транзакциях: филиалу Санкт-Петербург нужен экземпляр, который есть на
складе в Казани. Скрипт сам выбирает дефицитную модель, выполняет `XA PREPARE`
на двух узлах, затем `XA COMMIT`, проверяет результат в консолидированной
копии и демонстрирует откат при попытке повторного бронирования.

```bash
cd replication
bash distributed_booking.sh
```

Ожидаемый результат: в разделе «Состояние ПОСЛЕ транзакции» экземпляр
участника получает статус `бронь`, у координатора появляется заявка
`XA-…`, в консолидированной копии статус экземпляра — `бронь`, повторная бронь
возвращает `NOT_FREE`, а все шесть каналов репликации остаются в состоянии
`Yes`. Протокол прогона — `results/distributed_booking_log.md`.

Результаты проверок заносятся в `results/replication_log.md`.

## 5. Проверка схемы и данных

Подключение к узлу центрального офиса:

```bash
docker exec -it mysql-master mysql -uroot -ppassword --default-character-set=utf8mb4 campusrent
```

Полезные запросы:

```sql
SHOW TABLES;                              -- 22 таблицы и 10 представлений
SELECT COUNT(*) FROM equipment_units;     -- 775
SELECT COUNT(*) FROM requests;            -- 263
```

Выполнение отчётных запросов из файла:

```bash
docker exec -i mysql-master mysql -uroot -ppassword --default-character-set=utf8mb4 \
  --table campusrent < ../sql/08_queries.sql
```

Файл содержит 18 запросов: загрузка парка, структура парка, топ моделей,
поступления и их динамика, статусы заявок, затраты на ремонт, сроки аренды,
распределённый поиск техники.

## 6. Веб-приложение

Приложение подключается к узлу по параметрам `DB_HOST` и `DB_PORT`:

```bash
cd app
DB_HOST=127.0.0.1 DB_PORT=3306 DB_USER=root DB_PASS=password \
  php -S 0.0.0.0:8080
```

Интерфейс открывается по адресу <http://localhost:8080>. Доступны главное меню
со статистикой, просмотр и редактирование таблиц и отчётные формы.

Для подключения к другому узлу меняется порт: 3307 — филиал Санкт-Петербург,
3309 — филиал Казань, 3308 — узел консолидации.

Попытка добавить выдачу для экземпляра со статусом «аренда» завершается
ошибкой триггера — срабатывает ограничение целостности.

## 7. Перегенерация схем, данных и графиков

Генераторы детерминированы: при повторном запуске получаются те же файлы.

```bash
python3 tools/gen_data.py            # sql/03_test_data.sql
python3 tools/gen_diagrams.py        # diagrams/*.svg
python3 tools/gen_charts.py          # results/graphs/*.svg
python3 tools/gen_query_results.py   # results/query_results.md (нужен поднятый MySQL)
```

Сводка `results/query_results.md` генерируется из `sql/08_queries.sql` и данных
узла, а не пишется вручную: раньше она разошлась с фактическим выводом
`query_results.txt`. Генератор по умолчанию обращается к контейнеру
`mysql-master`; другой узел задаётся ключом `--node`, внешний сервер — ключом
`--client`.

Преобразование SVG в PNG выполняется утилитой `rsvg-convert`
(устанавливается пакетом `librsvg`):

```bash
cd diagrams
for f in *.svg; do rsvg-convert -w 1700 "$f" -o "${f%.svg}.png"; done

cd ../results/graphs
for f in chart_*.svg; do rsvg-convert -w 1600 "$f" -o "${f%.svg}.png"; done
```

При изменении структуры базы данных синхронизируются `sql/01_schema.sql`,
`docs/03_Логическое_проектирование.md` и описание отношений в
`tools/gen_diagrams.py`.

## 8. Остановка стенда

```bash
cd replication
docker compose down -v
```

Ключ `-v` удаляет тома с данными стенда.

## 9. Возможные ошибки

| Сообщение | Причина и решение |
|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop не запущен |
| `docker compose: command not found` | Не установлен плагин Compose; в старых версиях команда называется `docker-compose` |
| `port is already allocated` | Порты 3306–3309 заняты другим процессом; освободите их или измените проброс в `docker-compose.yml` |
| `ERROR 1406: Data too long for column 'EQ_STATUS'` | В команде `docker exec` пропущен `--default-character-set=utf8mb4` |
| `ERROR 1064 ... near 'CHANGE MASTER TO'` | Подключение к MySQL 8.4; стенд рассчитан на образ `mysql:8.0` |
| `Slave_SQL_Running: No` | Смотрите поле `Last_Error` в выводе `SHOW SLAVE STATUS` |
| `ERROR 1304 ... already exists` в `Last_Error` | DDL-скрипт (`sql/04`, `05`, `06`, `07`) запущен повторно на одном узле работающего стенда. В MySQL 8.0 `log_replica_updates` включён по умолчанию, поэтому DDL разносится по каналам и останавливает узел, где объект уже есть. Лечится пересборкой: `docker compose down -v && bash setup.sh`; DDL допустимо выполнять только до включения репликации |
| `ERROR 3898 ... filters with XA transactions` | XA-транзакция попала на узел, фильтр репликации которого исключает её таблицы. XA несовместима с фильтрами; см. `docs/06_Реализация_репликации.md`, п. 6.7 |
| `Table 'campusrent...' doesn't exist` | Скрипты загружены не по порядку; запустите `bash setup.sh` повторно после `docker compose down -v` |

## 10. Порядок демонстрации

1. Постановка задачи: компания сдаёт вузам технику, есть центральный офис и
   филиалы — `diagrams/01_network_scheme.png`.
2. Обоснование распределённой базы данных: данные и их потребители
   распределены, требуются фрагментация, репликация, распределённые запросы.
3. ER-диаграмма и схема базы данных: `diagrams/02_er_diagram.png`,
   `diagrams/03_db_schema.png`, нормализация до 4НФ, 22 отношения.
4. Схема фрагментации: `diagrams/05_fragmentation.png` — справочники
   реплицируются с основной копией, клиенты — без основной копии, техника
   фрагментируется по филиалам и консолидируется в ЦО, заявки проходят
   рабочий поток.
5. Работа с базой данных: вывод таблиц, два-три запроса из
   `sql/08_queries.sql`, срабатывание триггера при попытке выдать занятую
   технику.
6. Репликация: изменение тарифа на узле ЦО и его появление в филиалах,
   добавление вуза в филиале и его появление в ЦО и в другом филиале,
   попадание данных филиала в консолидированную копию.
7. Распределённая транзакция: `bash replication/distributed_booking.sh` —
   межфилиальное бронирование по протоколу двухфазной фиксации (две фазы,
   точка фиксации, откат при повторном бронировании).
8. Веб-приложение: таблица и отчётная форма.
9. Результаты испытаний: `results/query_results.md`,
   `results/integrity_tests.md`, `results/replication_log.md`,
   `results/distributed_booking_log.md`.

> Порядок важен: демонстрация распределённой транзакции меняет данные
> (экземпляр получает статус «бронь», появляется новая заявка). Чтобы вернуться
> к исходному набору, на котором построены `results/query_results.*`,
> выполните `docker compose down -v && bash setup.sh`.
