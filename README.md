# Проект распределённой базы данных
## «Сервис аренды техники для высших учебных заведений» (CampusRent)

Домашнее задание по дисциплине **«Распределённые базы данных и сетевые вычисления»**
МИЭМ НИУ ВШЭ, магистратура. Проект включает как реляционное проектирование
предметной области (модуль 1), так и построение распределённой БД на его основе.

---

## 1. Что это за проект

Компания **CampusRent** сдаёт в аренду учебную и лабораторную технику (проекторы,
ноутбуки, VR-шлемы, измерительные приборы, аудио- и видеооборудование и т. д.)
высшим учебным заведениям. Компания имеет **центральный офис (ЦО)** и **сеть
филиалов** в разных городах. Вузы арендуют технику у ближайшего филиала,
филиал хранит, выдаёт и обслуживает свою часть парка техники.

Именно сетевая структура компании (географически распределённые филиалы,
централизованная номенклатура и тарифы, централизованная отчётность) делает
**распределённую БД** обоснованным и естественным решением.

## 3. Быстрый старт

### Вариант А. Полный стенд с репликацией (Docker)
```bash
cd replication
docker compose up -d
# master: localhost:3306, slave: localhost:3307, consol: localhost:3308
```
Подробности — в `replication/README.md`.

### Вариант Б. Одиночный сервер (без Docker)
```bash
mysql -uroot -p < sql/01_schema.sql
mysql -uroot -p < sql/02_reference_data.sql
mysql -uroot -p < sql/03_test_data.sql
mysql -uroot -p < sql/04_views.sql
mysql -uroot -p < sql/05_triggers.sql
mysql -uroot -p < sql/06_indexes.sql
mysql -uroot -p < sql/07_users_grants.sql
mysql -uroot -p < sql/08_queries.sql
```

## 4. Использованные методы поддержки распределённости

| Метод | Где применён |
|---|---|
| Горизонтальная фрагментация | таблица экземпляров техники — по филиалам |
| Репликация с основной копией (моментальные снимки) | справочники НСИ |
| Репликация без основной копии (асинхронное распространение изменений) | клиенты (вузы, подразделения, представители) |
| Репликация с консолидацией данных | экземпляры техники, заявки, договоры, платежи, ремонт |
| Рабочий поток (workflow) | жизненный цикл заявки (филиал ↔ ЦО) |
| Распределённые запросы | поиск свободной техники по всем филиалам |
| Распределённые транзакции | бронирование и перенос техники между филиалами |

## 6. Что уже проверено

Проект не только спроектирован, но и фактически выполнен на сервере MySQL:

- все 8 SQL-скриптов выполняются без ошибок: создаются **22 таблицы**,
  **10 представлений**, **18 триггеров**;
- загружен набор тестовых данных (775 экземпляров техники, 263 заявки,
  114 договоров, 471 выдача и т. д.);
- все **18 отчётных запросов** возвращают корректные результаты
  (`results/query_results.txt`, `results/query_results.md`);
- проверены **11 контрольных примеров** ограничений целостности — все дали
  ожидаемый результат (`results/integrity_tests.txt`, `results/integrity_tests.md`);
- демонстрационное веб-приложение (`app/`) проверено: подключается к БД,
  показывает таблицы, добавляет/удаляет записи и формирует отчёты.

Проверку можно повторить командой `tools/run_local_demo.sh` (на своём сервере
MySQL) или развернуть стенд репликации `replication/setup.sh` (Docker).
